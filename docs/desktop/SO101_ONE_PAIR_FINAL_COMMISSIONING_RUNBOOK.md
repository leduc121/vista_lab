# VISTA SO-101 one-pair supervised commissioning runbook

**Status:** Software candidate only. No physical commissioning was performed for this closeout. Every step below is an owner/operator action; steps marked **OWNER SUPERVISION REQUIRED** must be observed and authorized by the hardware owner. This runbook does not authorize calibration, motor activation, or motion by itself.

**Target:** one SO-101 leader and one SO-101 follower connected to the VISTA Desktop Lab Station. Dual-arm operation and physical VLA execution are out of scope.

## Stop conditions

Stop before connection or motion if device identity, role, calibration, runtime version, safety configuration, initial-pose compatibility, operator authorization, or independent physical E-stop access is uncertain. Stop immediately on unexpected motion, stale/non-finite telemetry, an adapter/runtime fault, loss of a person-free workspace, or any safety limit. Do not retry blindly, recalibrate over a valid file, or resume after reconnect.

## Commissioning sequence

1. **Required hardware — OWNER SUPERVISION REQUIRED.** Confirm exactly one SO-101 leader and one SO-101 follower, their approved power supplies and USB cables, stable mounts, clear movement envelope, and an accessible independent physical E-stop. Name the operator and supervising owner.
2. **Required software — OWNER SUPERVISION REQUIRED.** Record Desktop source/package hash, OS, selected Robotics Python environment, LeRobot, Feetech SDK and pySerial versions. The locked project environment was installed and verified on this workstation with `uv sync --project edge/robot-runtime --locked --python 3.12`: Python 3.12.14, LeRobot 0.6.1, Feetech SDK 1.0.0 and pySerial 3.5. Recreate if absent with that exact command, then select `<Desktop repository>/edge/robot-runtime/.venv/bin/python` and the same authorized source checkout in Desktop Runtime Settings. This only makes the driver available; it does not connect a device or authorize hardware.
3. **Serial permission verification — OWNER SUPERVISION REQUIRED.** Verify the operator account can read/write the intended serial devices using OS diagnostics. Do not change group membership or permissions during a live robot session. Record permission errors and resolve them before connecting.
4. **Leader/follower identification — OWNER SUPERVISION REQUIRED.** Trace each USB cable to the physical arm. Record explicit role, stable device/profile ID, port path and OS serial identity where available. Select each role explicitly in Desktop; never use port order to infer role. Confirm the two ports differ.
5. **Existing calibration verification — OWNER SUPERVISION REQUIRED.** Inspect the role-specific LeRobot calibration entries in Desktop. Confirm each file is readable, schema-valid, role-matched and associated with the selected ID. Preserve a backup. Do not overwrite or “refresh” a valid profile.
6. **Supervised calibration if required — OWNER SUPERVISION REQUIRED.** Only if the owner confirms a profile is absent or invalid: establish neutral pose, clear workspace and E-stop readiness, then run the explicit guided calibration separately for leader and follower. Confirm each guided step before its bus write. Cancel on uncertainty. Never fabricate values; verify the newly saved file and readback before continuing. Existing valid files require no calibration.
7. **Safety configuration verification — OWNER SUPERVISION REQUIRED.** Confirm an owner-approved physical safety profile exists for this exact robot and adapter. The current source has no persisted approved physical profile: `edge/runtime.py` injects `position_limits_rad`, `velocity_limits_rad`, and `safe_stop` into `LeRobotSO101Adapter`; `edge/safety_controller.py` names the six joints and defaults to `hardware_enabled=False`, watchdog `.25 s`, and heartbeat `2.0 s`. The watchdog and heartbeat values are implementation defaults, not accepted hardware limits. The owner must provide exact device/role IDs, validated calibration files, all six position and velocity bounds, physical command-rate and stale thresholds, watchdog action, safe-stop/hold handler, initial-pose tolerance, reconnect/re-arm procedure, and the independent physical E-stop model-specific procedure. Do not use simulation values or infer a value. Without owner approval and a verified configuration, physical arming stays unavailable and commissioning stops here.
8. **Connection readiness — OWNER SUPERVISION REQUIRED.** Start only the selected Desktop Robotics runtime. Discover ports, confirm role-to-device mapping, connect leader and follower explicitly, confirm fresh finite six-joint state, calibration state, exclusive port ownership, and no fault. Connection does not authorize motion. Verify disconnect releases both port locks.
9. **Explicit arming — OWNER SUPERVISION REQUIRED.** Verify the independent physical E-stop is reachable and the operator has authority. Confirm there is no competing controller, safety diagnostics are clear, and the approved safety profile is loaded. Arm only through the approved explicit operator action. The current default configuration is hardware-disabled and physical arming is blocked.
10. **Supervised teleoperation — OWNER SUPERVISION REQUIRED.** Compare leader and follower initial measured poses against the approved tolerance without auto-alignment or homing. Obtain explicit owner authorization for the precise low-risk trial, duration, and limits. Start teleoperation explicitly with the operator holding the required deadman; keep the supervisor at the physical E-stop. Monitor all six joints, freshness, command rate and faults. No motion should start on connection or reconnect.
11. **Stop verification — OWNER SUPERVISION REQUIRED.** First verify Desktop software Stop under the owner-approved procedure. Confirm commands cease, control ownership releases and a fault/stop state is visible. Verify the separate physical E-stop independently as directed by its hardware procedure. Software Stop is not a physical safety circuit.
12. **Disconnect verification — OWNER SUPERVISION REQUIRED.** Under the approved stationary/disabled state, disconnect each device and confirm runtime status goes offline, commands remain blocked, locks release and no automatic resume occurs after reconnect.
13. **Digital Twin verification — OWNER SUPERVISION REQUIRED.** Compare live measured follower observations with the Desktop Twin only after the owner approves telemetry exposure. Confirm six channel order, units and gripper mapping; verify robot/controller identity, timestamps, sequence freshness and disconnect freeze. Keep commanded state visibly distinct from measured state. A local fixture or replay frame is not live telemetry.
14. **Recording verification — OWNER SUPERVISION REQUIRED.** With an authorized stationary or approved supervised session, record measured observations locally, stop, inspect timestamps/order, identity/calibration/session metadata and integrity status. Confirm no command trace is claimed when unavailable. No upload occurs without owner authorization and API-issued storage authorization.
15. **Simulation replay verification — OWNER SUPERVISION REQUIRED.** Select the locally recorded episode and verify preview, pause, speed, seek and cancellation. Confirm replay is visualization-only and produces no physical action. Reject corrupt or invalid metadata recordings.
16. **R1-to-Desktop identity handover — OWNER SUPERVISION REQUIRED.** Select one runtime owner for the session. Stop the other client and verify it is disconnected/offline before starting the selected one. R1 and Desktop must never concurrently use the same production MQTT Thing/client identity. Confirm sole ownership and approved environment before any authorized cloud session. Do not access Production with an already active identity without the owner’s separate authorization.
17. **WF03 integration — OWNER SUPERVISION REQUIRED.** Use only the latest approved Edge contract and backend-issued session/attempt authorization. Verify command receipt, acknowledgement, execution lifecycle, heartbeat, telemetry, stop, expiry, disconnect, deduplication and terminal outcome against the approved integration environment. Desktop defaults to deny authorization; do not bypass it or create routes/topics/identities.
18. **Evidence verification — OWNER SUPERVISION REQUIRED.** Confirm evidence references the correct execution, attempt, robot, runtime classification, outcome and recording. Verify storage confirmation from the Education API/backend before calling evidence persisted. Backend/S3 persistence and permissions are Claude/backend ownership. Never promote mock/simulation evidence to physical evidence.
19. **Safe shutdown — OWNER SUPERVISION REQUIRED.** Stop teleoperation, verify no active command/recording, release control, disable hardware output, disconnect both arms, stop the sole runtime owner, verify MQTT offline if used, and leave the physical E-stop accessible. Save logs and owner sign-off.
20. **Failure and recovery conditions — OWNER SUPERVISION REQUIRED.** On any failure, stop commands, use the independent E-stop if needed, keep the robot stationary, preserve logs/calibration files, and report the exact fault. Do not clear a latched safety fault, recalibrate, reconnect for motion, resume, alter AWS identity, or continue the workflow until the owner diagnoses and explicitly reauthorizes recovery.
