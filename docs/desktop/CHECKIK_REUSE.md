# CHECKIK review and reuse record

Reviewed on 2026-11-20. The CHECKIK checkout (Git root confirmed) has pre-existing user modifications, including the `VRTeleop` submodule and several frontend files. It was inspected read-only and left unchanged. There is no root README and no root `LICENSE`/`COPYING` file. Its root `requirements.txt` declares NumPy, Pydantic and WebSockets, but does not declare LeRobot, Feetech or serial-port discovery dependencies.

## Adaptation in this release candidate

`robot-runtime.js` is the legacy JavaScript safety boundary and is not a copy of the LeRobot driver. Blockly execution now goes through `edge/mujoco_simulation.py`, with a strict allowlist, active attempt authorization, a separate explicit simulation confirmation, expiry checks, bounded waits, and six measured MuJoCo joint states. The model is licensed separately from CHECKIK. Physical movement remains disabled.

No CHECKIK file was moved, deleted, or modified. No CHECKIK source file was copied. `edge/runtime.py` independently adapts the public LeRobot follower interface used by CHECKIK (explicit port, `calibrate=False`, calibrated-state gate, measured joint readback); CHECKIK's own controller implementation and its license status are not redistributed. The native Edge bundle built here includes MuJoCo, serial discovery and MQTT libraries; LeRobot itself remains optional and is not included in that bundle. The adapter therefore reports unavailable until LeRobot is separately supplied. The existing `checkIk/` directory inside Lab Station predates this change and remains as-is; the runtime does not load it into the installer.

## Required before physical adapter work

2. Build pinned dependencies natively on Windows/macOS/Linux and ship required third-party notices.
3. Validate serial readback and disconnect on isolated hardware with an operator; tests must remain simulated and issue no physical motion.
4. Complete OS-native device provisioning and connect backend-issued MQTT identity/policy to the transport. A loopback mutual-TLS broker acceptance test and packaged MuJoCo runtime are verified locally, but the MQTT transport is not yet connected to Education API provisioning or Digital Twin telemetry.
